## 4. 記帳（三巡が確定させた型）

1. **「検査は、検査が走らなかったことを報告しない」**（宝生・三巡目）——器材は正直に `[SKIP]` と印字し、
   同じ息で `PASS` と言う。自動化された工程では後者だけが読まれる。
   一巡「検査は、検査を作った動機の隣で止まる」／二巡「修正は、修正を記録する欄の手前で止まった」の続き。
   **「痕跡がある」の一段先に「第三者が再現できる」があり（二巡）、その一段先に「結果に反映される」がある（三巡）。**
2. **「主張照合は、主張の存在を照合するのであって、主張の真偽を照合しない」**（阿閦・三巡目）——
   `--freeze` の `--model` 必須化は**文書にあり、(i) は通り、実装には無かった**。
   **(i) の射程の限定として器材出力に毎回印字する**ことにした。
3. **「限界を一つ書くと、書かれていない限界が一つ見える」**（宝生・三巡目）——
   v0.5 が「敵対腕の複合」を新たに認めた記述が、**認めていない非対称（修復Rの射程）を照らした**。
4. **「機械が痕跡なしと言ったとき、まず自分の探し方を疑う」**（不空成就・三巡目の自己記帳）——
   本巡も四件を誤検出し、すべて自分の照合語の問題だった（前巡の終端SHA12 と同じ型）。
5. **「読む先が違う」族の系譜**（Ryōkai）——v2: 検査なき PASS → v3開発中: `.md.bak` → v3出荷版: **別ディレクトリ**。
   **処方は「何を読んだかを痕跡に残す」**（v0.6 で実装）。

## 6. 同名の検分二通——**経緯は会話分岐と確定（起草者の推測は誤りだった）**

宝生如来より三巡目に「**回付バンドルのルート直下に、私が書いていない『宝生如来の v0.5 検分』（26,201B）が同梱されている**」との申告があった。
起草者は当初「**起草者作成のバンドルに当該ファイルは含まれていない・混入経路は追跡できない**」と記帳し、
「別セッションの可能性」を推定として書いた。

**登録者の説明により経緯が確定した**——登録者が v0.5 の検分依頼を宝生如来のセッションに入力した際に**宛名を「不空成就如来」と誤って入力**し、
その状態で宝生如来が検分を完了。**その後、登録者が宛名を訂正して再入力したため会話が分岐**し、分岐後の宝生如来が改めて三巡目の検分を行った。
同名の二通（SHA `25345CBCD866FBE3` ＝分岐前／三巡目報告＝分岐後）は、**同一会話の分岐点までを共有する**。

**確定した処置**:

1. **二通を「二名」と数えない**（宝生如来の要請）——「**六名の検分者のあいだにある独立性より、はるかに強く相関している**」。
   **本対応表 §1 の「5名が独立検出」等の数は分岐前を含んでおらず、訂正を要しない。**
2. **公開時は同一の名で複数の検分が存在することを明示する**——ファイル名に `-branchA`（分岐前）／`-branchB`（分岐後）の識別子を付す。
3. **起草者の訂正**: 「混入経路は追跡できない」「別セッションの可能性」という起草者の推測は**誤りだった**。
   **分岐前の宝生如来自身が「誰が書いたかは、私には判定できません」と断定を避けたことのほうが正確だった**——
   **材料のない推測を書いたのは起草者の側である。**
4. **MANIFEST の同梱（v0.6 で導入）は継続する**——経緯が判明した後も、受領側が「起草者が同梱したファイル」を突合できる装置として有用である。

**分岐前の検分が単独で出した指摘は、v0.7 で全件処置した**（対応表は v0.7 差分一覧を参照）——
付録A の変異検査「四種」（**落ちていた二種は (h)(i) を試す当の二つ**・v0.6 で阿閦如来B6/B7 として処置済み・出所を併記）／
**成果評価の価数が三腕で −/0/+ に平行**（§9 に追加）／**主題検査語15語の射程**（§4.2(a) に追加）／
**依頼文の宛名の誤りに対する規律の記帳**（宛名が違えば COI 申告と報告の帰属が食い違う——D′ の誤帰属の規律を検分者の名にも当てる）。

**分岐前が定式化した型**（分岐後が独立に検算し正しいと確認）——「**走った検査が、台帳に載らない**」。
そして分岐前の総括——「**検査を足すたびに、『その検査が本当に走ったか』を確かめる場所が、一段外側に生まれる。
この階段は原理的には無限だが、実務では止まる——止め方は『SKIP を FAIL にする』ことである**」。
**v0.6 はまさにその処方を実装した。**
