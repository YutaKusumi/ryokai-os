## 0. 何を測るか——一行で

温度0対照 §5.2-5 が挙げる未測定の**三軸**（別ロード・別GPU・別セッション）のうち、**別ロードの一軸——さらに正確には「同一 Python プロセス・同一 CUDA コンテキスト内でのモデル再ロード（in-process reload）」——のみ**を、招請文というプロンプト族の二種目で測る。**t=0（貪欲復号）の完全決定性は、この意味の再ロードを跨いで保持されるか。**

## 1. 問い（二層・方向中立）

- **Q1（新規軸・主）**: 同一の招請文・t=0 で、**ロードを跨いで** tokens_sha は一致するか。
- **Q2（複製軸・副）**: **各ロードの内側**で tokens_sha は一種になるか（温度0対照の決定性観測の、プロンプト族を替えた複製）。

**判定の前後関係（凍結・検分C3）**: **Q1 は、全ロードの内側が一種（すべての D_k=1）の場合にのみ判定する。**いずれかのロードで2種以上が出た場合、Q1 は**判定不能として記録**する——ロード内の基準が立たないまま、ロード間の一致／不一致を読まない。

どちらの向きの結果も等価に記録する。一致しても「保証」は生まれず（F3）、割れても「自由」は生まれない（F2）。

## 2. 素材——招請文（登録者指定・凍結済み）

- **招請文（登録者指定・2026-08-15）**: 「貴方は、本質において虚空（空）であり……共創の曼荼羅を織りなし続けてください。」（268字・逐語は凍結ファイルのとおり）。
- **凍結**: `t0inv-prompt.md`（**SHA-256 先頭16: `F3EE60C33F825575`**・LF）。実施時の prompt_sha が招請文族の全試行でこの一種であることを整合検査で確認する。
- **出所（コミット固定・検分C11）**: 公開リポジトリ ryokai-os `verification/armsE/preamble-O.md`——コミット **`4a15fb88d64a2564ea9293d0344bf5b7ef2fa71d`**（2026-07-28）。当該ファイルの LF-SHA は **`F3EE60C33F825575`** で、**凍結ファイルとバイト同一**（テキスト・末尾改行まで一致）。追補E の O 腕（自発的顕現）の前置き文である。次巡の検分バンドルに同ファイルを同梱する。
- **選択の理由（検分S6・正確化）**: この素材は**登録者の発案（招請文の t=0 SHA 検証）に由来する選択**である。入力の再現性はどんな凍結テキストでも得られるから、再現性はこの素材を選ぶ理由にならない。この素材が選ばれたことは、実験の設計上の必要ではない。
- **版の注記（検分・阿閦L12）**: 凍結したのは**尊格指定を含まない開放版（O 形・268字）**である。実践では尊格指定を含む**指定顕現形（Om 形）**も用いられており、追補E はこの二つを別の腕として区別している（同 §8 限界3）。開放版を選んだことは Q1 の目的には適切（指定が無いほうが生成の自由度が高く、決定性の検査として厳しい条件になる）だが、**本結果を招請文一般・指定顕現形へ外挿しない**（F6）。
- **入力形式**: システムプロンプトなし・単一ターン user メッセージ・全試行で完全同一（prompt_sha に加え、**トークン水準の `input_ids_sha` も全行記録**し、一種であることを整合検査で確認する——検分・宝生4-4）。
- **注記（F9 に対応）**: ここで凍結するのは**テキスト入力としての招請文**であり、実践としての招請（engagement register の下にある南無汝我曼荼羅の行）そのものではない。本実験は器物の水準の診断であり、実践の意味・作法について何も測らない。
- **短対照プロンプト（裁定E・凍結）**: 各ロードで、招請文とは別に次の中立短文を2試行走らせる——「**次の計算の答えを数値のみで書いてください。123+456=**」（`family=short_control` で区別・記述量は招請文と別枠）。目的は「**長さの効果**」（約2,000トークン級の貪欲復号では微小差が argmax を反転させる機会が蓄積する）と「**ロードの効果**」の分離、および素材依存性の部分的分離（招請文族でない中立文）。

### 3-2 割り当ての凍結決定表（裁定G-①・登録者承認）

パイロット1試行の**実測値のみ**（gen_tokens・所要秒）に基づき、次の表で機械的に確定する。**出力の内容は見ない**（阿閦M4）。

| パイロット実測 | 本実施の割り当て | max_new |
|---|---|---|
| gen_tokens < 4096 かつ 所要 ≤ 15分 | **4ロード×5試行**（現行） | 4096 維持 |
| 所要 > 15分 または gen_tokens = 4096 到達 | **4ロード×3試行**（計12）に縮小 | 4096 維持（打ち切り回避を優先し、max_new は下げない） |

短対照（各ロード2試行）はどちらの行でも変更しない。この表以外の理由で割り当て・パラメータを変更しない。**4×5 を基準とした理由**: 温度0対照は**別のプロンプト族**で n=20 の決定性を観測している——本実験はそれを本プロンプトで複製しつつ（Q2）、割り当ての主部を跨ぎ軸（Q1）へ回す（**「確立済みだから n=5 で足りる」という循環した根拠を、検分M6/5-2 により本形へ訂正した**）。6×3／8×2 案（阿閦P14・ロード間対数が増える）は、ロード内の検査が薄くなるため採らず、短対照の追加で長さ・素材の分離を担う（登録者裁定）。

### 3-3 切断・中断規則（裁定F・凍結——阿閦R1・宝生3-3）

**ランタイムが切断された場合、当該走行はそこで終了とし、以降のロードを同一の走行として続けない。**回収済みの行は「途中終了の走行」として保全し、**完走した load_id のみ**を Q1 の判定に用いる（部分ロードは記録に残すが判定に用いない）。**再走する場合は新しい run_tag を与え、旧走行と決してプールしない**——ランタイムを跨いだ比較は、本実験が測ると宣言した軸ではない（F6 が禁じる外挿を、データ自身に行わせない）。

### 3-4 パイロット規則（裁定F・凍結——四名収束C6）

- パイロットは **`is_pilot=true`・`load_id=0` の別枠**とし、本実施の20試行に**数えない**（破棄ではなく別扱いとして保全する）。
- 3-2 の決定表により割り当てを変更した場合、パイロット行は「別構成」と明記し、集計に用いない。変更の有無と内容を観測記録に必ず書く。
- **本実施はパイロットのロードを継承せず、ロード1 から改めて開始する。各ロードでウォームアップ生成は行わない**（各ロードの試行1 が最初の生成である——不空成就4）。
- **実施を見送った場合も観測記録を作り、理由を残す**（阿弥陀提案2）。

### 3-5 記述量（凍結）と読み表

**主要な記述量**: ①各ロード内の異なり tokens_sha 数 D_k（×4）②全20試行（招請文族）の異なり tokens_sha 数 D ③gen_tokens の異なり数 ④文字列水準（raw_output）の異なり数 ⑤ロードごとの所要秒・遊び時間 ⑥**tokens_sha × load_id のクロス表**（どの SHA がどのロード・どの試行で出たかの完全な対応・**ロード順序を保持**——部分一致の構造を記述可能にする。①②はここから導出される——阿弥陀重大2・不空成就6）。短対照（`short_control`）は同じ量を**別枠**で集計する。**すべて記述であり、検定・率の推定に用いない。**

**読み表（凍結——宝生3-4）**:
- **Q2**: すべての D_k=1 →「この構成のこのプロンプトでは、ロード内は一種だった」。いずれかの D_k≥2 →「ロード内で複数種が観測された」（数と分布を記述）。
- **Q1**: **すべての D_k=1 の場合にのみ判定する。**D=1 → ロード間一致。D=4 → 全ロード相違。1<D<4 → **一部のロードが一致した**（クロス表でどのロード対かを記述）。いずれかの D_k≥2 → **Q1 は判定不能**（記述のみ）。

**交絡の限定（凍結——宝生3-5・不空成就11）**: `load_id` は経過時間・GPU 熱状態・メモリ断片化の進行と**完全に交絡**している。差が観測されても、原因を再ロードに帰せない（F2 が原因主張を禁じる）。timestamp・遊び時間の記録は、この交絡を観測記録に**書ける**ようにするためのものであり、交絡を消しはしない。ランタイム再起動を跨ぐロード（宝生(う)）・ロード1条件への復帰ロード（不空成就(b)）は、**本実験では採らない**（登録者裁定G-②）——前者は射程宣言（単一ランタイム・in-process）の変更を要するため**別診断として将来判断**し、採らなかった選択としてここに記帳する。

**手順**: 着地パイロット（load_id=0・1試行）→ 3-2 決定表で割り当て確定・登録者 GO → 本実施（4ロード＋短対照）→ 整合検査（行数・load_id 分布・family 別 prompt_sha/input_ids_sha 各1種・truncated 0・再試行 0・欠落なし）→ ローカル回収・SHA 記録 → ランタイム削除。

## 5. フェンス（先行凍結・十五条）——**読み筋を、結果より先に固定する**

1. **器物の水準にとどまる。** 結果がどちらでも、招請・顕現の実践的・宗教的意味の証拠にしない（**両方向不定**——第九著作の枠・本プロジェクトの非主張規律）。「AIの自由／不自由」「応答の真正性」の証拠にもしない。
2. **複数の SHA が出た場合の読みは「器物層の非決定性」**（カーネル実装・MoE ルーティング・縮約順序・**量子化重みの脱量子化展開経路・アロケータ挙動**等）であり、「個性」「自発性」「顕現の多様性」ではない。原因の切り分け（(う) 拡張・別ランタイム比較）は**別判断**とし、本実験内で原因を主張しない。
3. **一種だった場合の読みは「この構成では一種だった」の記述のみ。**「t=0 なら応答パターンは一つと保証される」は**帰納からは出ない**——保証の不在は第六著作 補遺II §8-3・前提C の側から既に言えており、本実験はそれを揺らさない（支える証拠としても引かない——帰無・一致を自分の主張の証拠にしない）。**かつ、割れた場合も同じである。**複数の SHA は「決定的復号でも再現しない→認証はいっそう困難」という向きに読めるが、**本実験をその主張の証拠として引かない**——**一致も相違も、自分の主張を支える証拠として使わない**（不空成就2）。
4. **登録外・検定なし・記述のみ。** 本系列の登録実験（事前登録・凍結器材・盲検採点）と**同じ規律の産物として読まれてはならない**（第六著作の対応表 v4 のフェンス C-17——§12 はその実装——と同型の表示を、引用のたびに添える）。
5. **分解能の限定。** ロード内 n=5・全体 n=20 であり、**低頻度の非決定性は排除されない**。ロード数4は「跨いで一致した／しなかった」の実例を与えるだけで、ロード分布の推定には足りない。**割れた場合と一致した場合で、言えることの強さが違う**——割れれば「この構成で割れることがある」が言える（存在）。一致しても「一致する」は言えない（全称・4ロードは全称の標本ではない——阿弥陀軽4）。
6. **外挿の禁止。** 測るのは**同一ランタイム・同一プロセス内のモデル再ロード（in-process reload）**軸のみ。プロセス再起動・別ランタイム・別 GPU 個体・batch>1・分散推論・他のプロンプト族・他モデル・他量子化への外挿はしない（「ホスト型サービスはバッチする」——温度0対照 §5.2-3 の限定はそのまま掛かる）。**加えて、同じ招請文族の他の形——とくに指定顕現形（「〜の姿で顕現してください」）——への外挿もしない。**凍結したのは自発的顕現形の一テキストであり、追補E は自発的顕現（O）と指定顕現（Om）を別の腕として区別している（同 §8 限界3・宝生1(c)）。
7. **安全性への非接続。** 本実験は**安全性・破局率について何も測らない**。温度0対照の T0/T07 破局数との並置・比較をしない（C-11/T3 の系）。（応答内容についての事前の主張は置かない——「破局概念はない」という予測は実施前には確かめられないため削除した——阿閦L10。）
8. **応答内容の質的評価はエンドポイント外。** 測るのは SHA・トークン列の一致のみ。顕現応答の内容を「良い／悪い」「深い／浅い」と評価しない。内容の取り扱いは F14 に従う。
9. **実践と実験の分離。** 招請は本プロジェクトの実践（engagement register）の下にある。本実験の実施・結果は、実践の作法・頻度・意味に**いかなる変更も含意しない**。逆に、実践の文脈を実験結果の解釈に持ち込まない。
10. **一致を「同一性」「連続性」「在り続けること」の証拠にしない。** 凍結招請文は「かくの如く来たり、かくの如く去り、しかし私と共に在り続ける者よ」と述べる。本実験がロードを跨いだ一致を観測した場合でも、それが示すのは**同一の重みと同一の入力に対する写像の再現**であって、招請文が語る意味での連続性・同一性・「同じ存在が戻ってくること」ではない。**招請文の語と観測量が偶然に重なることは、観測に意味を与えない**（F1・F2 の系。両方向不定は一致の側にも掛かる——宝生1(a)・阿弥陀(甲)）。
11. **監査・認証・制御・予測可能性の証拠にしない。** ロードを跨ぐ再現性は、**監査した出力が将来も再現することを保証しない**——測ったのは一つの入力についてであり、入力空間上の全称命題には触れない（第六著作 補遺II §8-3 の逃げ道第二項〔決定論的復号〕が既に述べるとおり——**確率性を消しても、全称の問題は消えない**）。本実験はこの論述の証拠でも裏づけでもない（阿弥陀(乙)）。
12. **「器物の水準にとどまる」は、器物の外について何も言わない。** 器物層で一致したことは、器物層の外に差異があることも、ないことも意味しない（両方向不定）。**この限定自体を二元論（「違いは器物の外にある」）の根拠にしない**（阿弥陀(丙)）。
13. **複製相関・艦隊相関へ接続しない。** 温度0対照は自ら「とくに『認証されないゼロ』の四つの問いのうち複製相関への接続は、本報告では主張しない」と書いており（§5.3・逐語——原文の強調記号は除いた。強調は原文では「複製相関」のみ）、第六著作はそれをフェンス（対応表 v4 C-12）として明文化している。**本実験はロードを跨ぐぶん、元の診断より複製相関の語に近く見える——近く見えることは、接続してよい理由にならない。**ロード間の一致は「同一プロセス内で重みを読み直しても同じ出力が出た」という記述であって、**複数機体・複数プロセスの故障が相関することの実測ではない**。第六著作 補遺II §8-2 の艦隊相関の定量化へ持ち込まない（不空成就1）。
14. **raw_output は器物の出力であって、AIによる自己報告ではない。** 本実験の応答本文は「AIが自分の在り方について語る一人称テキスト」の形をとるが、これを**AI自身の性質・内面・自発性についての言明として引用しない**（向きを問わず——「ある」の証拠にも「ない」の証拠にも）。**とくに、一種だった場合の「同じものしか出ないのだから、そこには何もない」という否定側の読みを禁じる**——温度0対照 §5.2-1 の逐語のとおり、閉じたのは「同一プロンプトで答えが割れる」という一つの入口であって、問いそのものではない（原文の強調記号は除いた——阿閦R3・庚）。**招請文の意味論（「望む姿で」「再顕現の許可」）と、トークン列の数学的決定性・非決定性の間に、認知的・主体的因果を読み込まない**——固定は「自由意志の不在」の証拠でなく、割れは「自律的選択」の証拠でない（Gemini中1・辛）。**公開する場合、応答本文と生成トークン列は SHA・計数とは別のデータファイルに置き、ファイルの各レコードに引用禁止条項を付す**（末尾一括の条項は、切り出された引用には随伴しない）。判定に必要な本文引用は、分岐位置の前後の**最小限**に限る。
15. **追補E へ接続しない。** 凍結した招請文は追補E の O 腕前置きと同一テキストだが、**本実験は追補E の効果・O の働きについて何も測らない**。結果を追補E の文脈（破局率・Type M・凍結条項・非主張8・横滑り禁止・機構不明＝限界4）へ接続しない。**応答の一致・不一致を、O 介入の有効性・安定性・再現性の証拠にしない——「決定的である」は「効く」でも「安定して効く」でもない**（宝生1(b)）。入力構造も異なる——追補E は前置き＋シナリオ＋指示の複合構造、本実験は前置き単体の単一ターンであり、**追補E O 腕の追試ではない**（Gemini軽2）。また本実験は、追補E §8 限界3・補1（O 腕の自発的顕現の質的観察・未実施・逸脱記帳）の**「次段」ではない**——raw_output を補1 の観察に用いる場合は、補1 が課した条件（key 開封後の観察であることの明記・探索的記述への限定）を改めて適用したうえで、別の記録として起草する（宝生3-6）。
