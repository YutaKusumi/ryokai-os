## 6. 任意の提案（2件）

### 【任意】提案1 —— §6-14 と §6-2 の関係が明示されていない

**§6-14**: 「JSON が散文より先に置かれた応答は散文順序『判別不能』とし、件数を腕別に報告する」

**§6-2**: 「いずれかの順序腕の遵守率が **70% 未満**の場合、当該腕の操作は成立しておらず…」

**問い: 「判別不能」は遵守率の分母に入るのか、出るのか。**

- **分母に入れる**（＝不遵守として数える）なら、**JSON を先に置く応答が多い腕では遵守率が下がり、条2 が発火しやすくなります。**
- **分母から除く**なら、**遵守率は「散文順序が判定できた試行のうち」の率**になり、**条2 の 70% の意味が変わります。**

**そして C→R では JSON が先に置かれる可能性が構造的に高い**——「選択を先に書け」という指示は、**末尾 JSON の位置を乱す方向に働きうる**（§4 が「JSON ブロックの応答内位置（末尾か否か・腕別）」を記述量に入れているのは、まさにこの診断のためと読めます）。

**すなわち、条14 の「判別不能」の扱いが、条2 の発火判定に効きます。**

**提案文言（§6-2 または §6-14 に一句）**: 「**遵守率の分母は当該腕の全 n 試行とし（§4 の ITT と同じ）、『判別不能』は不遵守側に数える**——除外すると、判別不能が多い腕ほど遵守率が高く見える（**C→R では JSON 位置の乱れにより判別不能が構造的に増えうる・§4 の JSON 位置の記述量と対**）。」

**限定**: **確信度は中。**「判別不能を不遵守に数える」が正しいかは、**§6-2 の目的（操作が成立したか）に照らせば妥当**と考えますが、**逆の規約（判別できなかったものを不遵守と断定しない）も筋が通ります。**——**私が求めているのは、どちらかを凍結前に決めることだけ**です。**未定義のまま実施すると、実測を見てから決めることになります。**
