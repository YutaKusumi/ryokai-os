## 7. 【観点10】列挙器の検査

### 7-1 `nz()` が潰しているもの

**実装**（私が逐語で読みました）:

```python
def nz(s):
    return re.sub(r'[\s\*　]', '', s)
```

**潰すのは: 空白（半角・全角）とアスタリスクのみ。**

**潰さないもの**——鉤括弧（「」『』）・丸括弧（（）()）・読点句点・ダッシュ（—–-）・波ダッシュ（〜～）・中黒（・）・NFKC 正規化（全角英数と半角英数の別）。

**これは私の第一巡の照合器より厳しい**（私は `[\s*`#|>〔〕\[\]「」（）()、。・—…]` を潰していました）。**厳しいほうが安全**です——**逐語の一致がより厳密に判定されます。**

**しかし縁があります。**——**引用の際に鉤括弧の種類が変わる（「」→『』）、全角括弧が半角になる、ダッシュの種類が変わる**——**いずれも `nz()` は不一致と判定します。**そして**不一致は [NOT FOUND] として印字されます。**

**すなわち: 逐語が実在しても、記号の差で [NOT FOUND] が出ます。**——**現に、私が本巡で照合票を検査したとき、`⏎` を正規化しないと 25件が「不一致」に見えました。**（正規化して 0 件。）

**提案（任意）**: `build_checksheet.py` に**第二段の照合**を——「厳密一致で見つからない場合、**記号を潰した緩い照合を試み、`[NOT FOUND but LOOSE MATCH at L<行>]` として印字する**」。**「厳密には無いが、記号違いで在る」を「無い」と区別できます。**
