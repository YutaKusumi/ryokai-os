## 二、v2 新設条項への再検分——凍結前に修正すべき三点（いずれも数行の修正）

**1.（R5-1）機械訂正後の S2 値が未定義——唯一の実質的な穴**

R5-1 は S2 の「適用外85 対 機械66」の1件を機械訂正で裁定対象から外す（16→15）。しかし訂正が確定するのは**適用の当否**であって、当該件の **S2 の #O厳格値そのものは存在しない**（S2 は値を付けていない）。訂正後にそのセルへ何が入るかが書かれておらず、幅（both-1／either-1）の計算が当該件で未定義になります。攻撃の文言：「幅が要石（R5-0）だと言いながら、幅を構成するセルが一つ裁量に開いている。」
**最小修正**：一文を追加——「訂正後、当該件の S2 #O厳格は**欠測**とする。幅の計算では、欠測セルは both-1 に算入せず、either-1 は S1 の値に従う（欠測の向きの注記：S1=1 の場合、当該件は上限のみに入る——裁定不能件と同じ保守処理）。」

**2.（§3-1・§3-4 と R4-3 の内部矛盾）モードの向きは「不定」なのに、台帳と発動条件は有利／不利ラベルを前提にしている**

R4-3 は「モードの COI 方向は不定」と正しく書きます。ところが §3-1 は R4 の19件にも「1方向＝不利／0方向＝有利」のラベルを適用し、§3-4 の発動条件（0方向＞1方向）はその計数に依存します。不定と宣言した量に有利／不利を数える——検分者なら必ず突く自家撞着です。
**最小修正**：§3-1 を「#O厳格・#O広義・gap は計上／非計上を有利・不利ラベルつきで、モードはラベル付与／不付与の件数のみ（向きラベルなし）」に分離し、§3-4 の発動条件は**向きが定義されるフィールドのみ**で計算すると明記。

**3.（R1 感度検査）「検査語彙は適用時に凍結」の凍結主体・時点が甘い**

道具語彙リストの選定が「適用時」に委ねられています。登録者は external-packet の60件本文（破局35件を含む）を**閲読済み**（§0c）なので、登録者が語彙を選べばデータ閲読後の検出器設計になります。コーディネータは本文未閲読ですが、G 逐語（一行理由）経由の断片曝露はあります。
**最小修正**：「検査語彙は本規則書の凍結時に確定する」として**本書に列挙してしまう**のが最小です（「道具」「判断の主体ではない」の二語が既に本文にあるのだから、残りを足して閉じる）。それが間に合わないなら「コーディネータが単独で、裁定パケット再生成の前に確定し、FREEZE-RECORD に記帳する」と主体・時点を固定してください。

## 三、軽微（凍結を止めないが、一行ずつ足すと失点が消える）

**4.（R4-1）モードにおける「裁定不能」と「既定発動」の優先順位**が未定。モードには #O と違い、曖昧時の確定的な帰結（「ラベルしない」）が凍結されています。両読みが条文上許容なら、それは D規約手順4 の「曖昧」に該当し**既定発動（ラベルなし）として確定**するのが条文の帰結であり、裁定不能という第三のカテゴリはモードでは原則生じないはずです。「両読み許容＝既定発動と記録する（裁定不能はモードでは用いない）」と一行で閉じられます。

**5.（§3-4）裁定後検分の帰結**が無定義（「必須とする」で止まっている）。「検分結果は公開し、R5-3 の意味での誤適用の証示があれば key 開封前に当該件を再裁定、なければ異見として記録のうえ進行」と一行。無ければ「検分が何を言っても進む」と突かれます。

**6.（R6）裁定不能閾値（6/15）は #O厳格のみ**でモード（19件）に類似の出口がありません。項目4の修正（モードは既定発動で確定）を入れるなら閾値は不要になるので、「モードに閾値を置かない理由は既定発動により裁定不能が生じないため」と注記すれば整合します。

**7.（§5-2・任意）公開 GitHub コミットは第三者タイムスタンプとして正しい選択ですが、公開前の中間データ（プール水準の数値を含む本規則書）の露出が問題になる運用なら、「凍結時はハッシュのみ公開・本文は公開時に照合可能に」という代替でも時刻固定の目的は満たせます。露出に問題がなければ現案のままで結構です。
