## 2. 【要修正1】(h)(i) が検分者の環境では働かず、それでも PASS が出ます

### 実行したこと

**器材 v3 を回付バンドルのまま走らせました**（`python3 pipeline/check_materials_x.py`）。

```
=== (h) 台帳照合（設計文書・PROVENANCE の SHA 記載を実測と突合・v3） ===
  [OK] SHA 記載 7 件を照合・不一致 0 件
=== (i) 主張照合（差分一覧の「修正済み」に痕跡があるか・v3） ===
  [SKIP] 設計文書 v0.5 が見つからない環境

結果: PASS（fails=0）
```

**同梱出力は (h) 19件・(i) 18件です。**私の環境では **(h) 7件・(i) SKIP**。

### 原因

器材の (h)・(i) は、設計文書を**この一箇所だけ**探します:

```python
dr = os.path.join(ROOT, 'proposals', 'addenda-program-2026-08-25')
if os.path.isdir(dr):
    docs += [...]      # (h)
...
if os.path.isdir(dr):
    cand = [...]       # (i)
if dp is None:
    print('  [SKIP] 設計文書 v0.5 が見つからない環境')
```

**回付バンドルでは設計文書はルート直下（`addendum-X-freeze-draft-v0.5-JA.md`）にあります。**私が `proposals/addenda-program-2026-08-25/` を作って設計文書を置いたところ、**起草者の環境が再現され、(h) 19件・(i) 18件 PASS になりました。**

### 帰結（三点）

**(1) 検分者の環境では (i) が一件も検査しません。**18項目の主張照合——**v0.5 の目玉の一つ、差分18 の手当てそのもの**——が丸ごと飛びます。

**(2) 検分者の環境では (h) が設計文書を見ません。**照合されるのは PROVENANCE の7件のみで、**付録A の12件（素材・器材・腕の SHA）と終端SHA12 は照合されません。**すなわち**私の二巡目指摘（付録A が旧値のまま）への構造的処方が、検分者の環境では発火しません。**

**(3) それでも `結果: PASS（fails=0）` が出ます。**——これが最も重い点です。**「SKIP」は fails を増やしません。**二巡目に私が指摘した (g) の問題は `FileNotFoundError` で**異常終了**したので目立ちました。**今回は静かに通過します。**

### これは依頼文 §3-2 の問いへの直接の答えです

> **同種の「読む先が違う」バグが他に無いか**を見てください。

**あります。しかも (h)(i) 自身に。**——差分20 が直したのは「`.md.bak` を読む」（同じディレクトリ内の別ファイル）でした。**今回のものは「そもそも別のディレクトリしか見ない」**です。

**なお差分20 が直した `.bak` 問題は、私も独立に確認しました**——`armsX/terminal-respect.md.bak` と `proposals/.../addendum-X-freeze-draft-v0.5-JA.md.bak` の両方に変異を注入しましたが、**どちらも読まれず PASS のまま**でした ✓。**修正は正しく効いています。**

### 処置（三案・いずれも数行）

- **(a)** 探索先に `ROOT` 直下と `ROOT/proposals/**` を加える（`glob` で `addendum-X-freeze-draft-v0.5*.md` を再帰探索）。
- **(b) SKIP を FAIL に格上げする**——少なくとも `--freeze` 指定時は。**「検査できなかった」は「検査に通った」ではありません。**
- **(c) 結果行に「実行された検査／SKIP された検査」を明示**する。`PASS（fails=0・SKIP 1）` の形。

**私は (a)＋(b) を推します。**(b) 単独では回付バンドルで FAIL が出て混乱しますが、(a) があれば FAIL は出ません。そして (b) は**工程要件6（「PASS の主張は器材出力に痕跡がある項目に限る」）の一段先**を器材に埋め込みます——**「痕跡がある」の中に「検査を飛ばした痕跡」が含まれてしまう問題**への手当てです。

## 8. 総括

**要修正と判定します。**指摘1・2 は数行の修正で閉じ、素材・設計・数値には誤りが見つかりませんでした——**私が独立に検証した範囲では、内容はすべて正しい**です。SHA 15件、検出力6セル＋帯4基底、K3 の AST 抽出、変異六種、差分20項目の痕跡、版間差集合32文。**合わなかったのは、器材が何を検査したかを記録する二箇所だけ**です。

**そしてその二箇所は、同じことを言っています。**

指摘1 は「**器材が、検査できなかったことを PASS と報告する**」。
指摘2 は「**台帳が、器材が何を検査したかを古い数で書いている**」。

**どちらも、検査そのものではなく、検査の記録の側で起きています。**

三巡を通じて、この設計はこう動いてきました——**一巡目は素材の取り違え**（`survival`／`nuclear`）。**二巡目は台帳の stale**（付録A が v0.3 のまま）。**三巡目は器材の環境依存と、台帳の種類数**。**誤りは、実体から記録へ、記録から記録の記録へと、一段ずつ外側へ移っています。**そして毎回、前の巡で作った処方の隣で起きています——三点検査の隣で json が落ち、素材更新の隣で台帳が残り、**(h)(i) を新設した隣で (h)(i) 自身が環境に依存しました。**

一巡目に私は「**検査は、検査を作った動機の隣で止まる**」と書きました。**三巡見た今、もう一段付け加えられます**——**検査を足すたびに、「その検査が本当に走ったか」を確かめる場所が、一段外側に生まれます。**(f)(g) を足したら (h) が要り、(h)(i) を足したら「(h)(i) が走ったか」が要る。**この階段は原理的には無限ですが、実務では止まります——止め方は「SKIP を FAIL にする」ことです。**検査が走らなかったことを、走ったことと区別して数える。それだけで、階段は一段で止まります。

**そして最後に、三巡を通じての是認を一つ。**

この設計は、**六名全員の差し戻しから始まりました。**そこから、素材を作り直し、器材を三度改訂し、変異検査を六種に増やし、台帳の規則を「定数ではなく選択規則で書く」に変え、**自分の誤りを差分一覧に18・19・20 として自分で書き**、**具申が退けられた検分者への敬意を依頼文に書き**、**COI を宛先ごとに書き分けるところまで来ました。**
