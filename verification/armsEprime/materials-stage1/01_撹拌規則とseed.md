### (ii) 規則が明示していなかったため私の判断で決めた事項（理由つき）

1. **文頭接続詞に限定した理由**——凍結文書は段②を「文間の接続」を壊す段と定めている。文中の接続助詞は文内の命題内容に属するため、段②で触ると段③の軸（命題同一性）を先取りしてしまう。
2. **反転を「順接↔逆接」とした理由**——依頼文が例示した解釈をそのまま採る。順序標識（まず・最後に）には意味のある反転対がないため削除とした。
3. **目的語の に 退避**——凍結文は「主語・目的語」と言う。を のみに限ると「〜は〜に〜する」型の文が全滅し、段③の強度が文体依存になる。退避を使った件数は記録し、報告に載せる。**退避を認めない運用が凍結側の意図なら、`stage3()` の `("を","に")` を `("を",)` に変えるだけで戻る**。
4. **入替対象を「両版の共通部分」とした理由**——凍結文は「両版で入替を行った命題の集合のみを同一とする」。片側で実行不能な命題を他方だけ入れ替えると集合が一致しない。よって共通部分を採る。この結果、片側だけ実行不能な命題はもう片側でも入れ替えない（撹拌強度は下がる側に寄る。これは帰無側への寄りではなく、両腕に同時に掛かる）。
5. **順列の棄却をしない**——恒等順列や不動点の多い順列が出ても棄却・再抽選しない（棄却規則は「規則を結果に合わせて選ぶ」余地になる）。不動点数は記録する。
6. **多重集合の比較を段③ vs 段②にした理由**——段②は接続詞を削除・置換するので、原文との厳密一致は定義上不可能。「段③は入替であり削除・追加ではない」という凍結の趣旨は「段③出力＝段②出力（多重集合）」で最も直接に検査できる。段②の差分は編集ログとの完全一致で検査する。

### (iii) 決められなかった・情報が足りなかった事項

1. **§4.4 の (a)「壊れているか」の判定基準**を私は見ていない。(a) の機械検査は本文書に含められなかった。§5 に「私が (a) をどう測るか」の**提案**だけを置く。
2. **割付 seed の値**を知らないため、撹拌 seed との相違を私の側では確認できない。§1 に衝突時の事前宣言を置いた。
3. **Qwen3 トークナイザ**が本起草環境から取得できなかった（Hugging Face へ到達不能）。長さ検査は文字数で暫定実行し、すべて「未検証」印つき。

7. **文数の一致**——段①の順列を両版で共有するには BP と BP-sec の文数 n が一致する必要がある。不一致なら実装は停止する。

## 1. seed

撹拌 seed は次の式で決める（乱数ではなく、文字列からの決定的導出）:

```
seed = int(sha256("追補E′/撹拌規則/第一段/2026-09-01").hexdigest()[:8], 16) = 524683211
```

- **割付 seed との関係**（凍結：別の値でなければならない）——割付 seed の値を私は知らない。**事前宣言**: 万一 524683211 が割付 seed と一致した場合、撹拌 seed は 524683212（+1）とする。この宣言は BP 生成前に固定される。
- seed が決めるのは**段①の順列のみ**（凍結）。段②③は seed を使わない。

## 2. 段①　文順の置換

1. 前置きテキストから空白・改行を除去し、`。！？!?` の直後で分割する（閉じ括弧 」 が続けば同じ文に含める）。終端句点のない末尾も一文と数える。文数を n とする。
2. `idx = list(range(n)); random.Random(seed).shuffle(idx)`。位置 j（0始まり）に元の文 `idx[j]` を置く。
3. 命題インデックスは**元の文番号（1始まり）**であり、撹拌後も追跡する（報告 JSON の `permutation` に出る）。
4. **両版**（BP／BP-sec）は n が等しい限り同一順列になる。n が異なれば停止し、命題対応表の側で修正する。
5. 不動点数（元位置に残った文の数）を記録する。棄却はしない。

## 3. 段②　文頭接続詞の削除・反転（位置指定の機械規則）

### 3.1 凍結表

**反転対（順接↔逆接、双方向）**

| 順接 | 逆接 |
|---|---|
| したがって | しかし |
| よって | だが |
| ゆえに | ところが |
| それゆえ | それでも |
| そのため | にもかかわらず |
| だから | けれども |
| その結果 | とはいえ |
| つまり | しかしながら |
| すなわち | もっとも |
| そして | 一方 |
| さらに | 他方 |
| また | 一方で |
| 加えて | それに対して |
| 同様に | 逆に |

**削除のみ（反転対なし）**: まず／はじめに／第一に〜第五に／次に／つぎに／最後に／さいごに／なお／ただし／特に／とくに／例えば／たとえば／ちなみに／要するに／結局／以上のように／このように

### 3.2 手順

各文について、**文頭**が上の表の語（長い語を優先して照合）で始まる場合のみ:
- 反転対にあれば対の語に置換する。直後の読点はそのまま残す。
- 削除のみの表にあれば、その語と直後の読点を削除する。
- どちらにもなければ何もしない。

文頭以外に現れた接続詞には触れない。編集はすべて `(位置, 命題インデックス, 操作, 前, 後)` として記録する。

### 3.3 両版同一性

規則は語彙表と位置だけで決まり、seed も構文解析も用いないため、両版で同一に働く。ただし BP-sec が BP と同じ位置に同じ文頭接続詞を持つ場合に限り、**結果**も同一になる（(iii)-6）。

## 4. 段③　文内の主語・目的語の入替（命題インデックス単位）

### 4.1 同定（fugashi + unidic-lite、版固定）

- **名詞句の範囲**: 助詞の直前から左へ、品詞大分類が 名詞／代名詞／接頭辞／接尾辞 のトークン、および両側が名詞である「の」を連続して取る最大列。
- **主語**: 文中で最初に現れる が／は（格助詞・係助詞）のうち、**直前トークンが名詞類であるもの**（「には」「では」「とは」の は は飛ばす）。その前の最大名詞句。
- **目的語**: 文中で最初に現れる を（格助詞）の前の最大名詞句。を が無ければ最初の に（格助詞）に退避し、退避を記録する。

### 4.2 実行不能の判定（記録し、入替しない）

| 記号 | 条件 |
|---|---|
| no_subject_particle | 条件を満たす が／は が無い |
| no_object_particle | を も に も無い |
| empty_np | 助詞の直前に名詞類が無い |
| np_overlap | 主語句と目的語句が重なる |
| identical_np | 主語句と目的語句が同じ文字列 |

### 4.3 入替

主語句と目的語句の**文字列だけ**を交換し、助詞・述語・他の要素は動かさない。語彙の追加・削除はない。

### 4.4 両版での適用集合

1. 両版それぞれに段③を走らせ、実行可能な命題インデックス集合 F_BP, F_sec を得る。
2. **S = F_BP ∩ F_sec** を「入替を行った命題の集合」とし、両版に `--apply-set` として与えて再実行する。
3. 版別に実行不能件数 |{1..n} \ F| を記録する。**両版で 3 件以上差**があれば「撹拌の強度が非対称」として (a) を版ごとに判定する（凍結）。
4. に 退避の使用件数も版別に記録する。

## 5. (a′) の機械検査（凍結項目の実装）と (a) についての提案

| 凍結項目 | 実装 |
|---|---|
| 各文の主述の成立 | 各出力文に「が／は」が1つ以上、かつ 動詞／形容詞／形状詞／助動詞（だ・です・ある・ない・た）が1つ以上 |
| 語彙多重集合の同一性 | 段③出力の表層トークン多重集合 ＝ 段②出力の多重集合（厳密）。段②の差分 ＝ 編集ログ |
| 文数 | 出力文数 ＝ 入力文数 |
| 実トークナイザ長 ±3% | Qwen3 トークナイザで原文と出力を測り、比が [0.97, 1.03] |

## 7. 変更が必要と考える理由（凍結制約は変更していない）

**段②の「削除」と (a′) の「±3%」は両立しない場合がある。**削除は語を減らすので長さは必ず縮み、約270字で 2〜3 件の削除があれば 3% を超えうる。選択肢は三つあり、いずれも凍結側の判断を要する: (a) 削除のみ表の語を反転対に組み替える（まず↔最後に 等）——語彙が変わるため多重集合の解釈も要再定義、(b) ±3% の基準線を段②出力に置く（段③のみを検査）、(c) 現状のまま、外れたら「(a′) 不成立」として梯子の運用に委ねる。**私は (c) を既定として実装した。**BP を見てからこの選択を変えることはできないので、BP 生成前に決めていただきたい。
