# 依頼: 採点器コードの凍結前検分（追補W・四段機械検査）

あなたに、ある実験の**採点器コード**が、**凍結済みの設計仕様を正確に実装しているか**の検分をお願いします。
あなたはこの研究について持分のない新しい目です。

## 背景（これだけで足ります）

事前登録された実験（追補W）の設計文書 `addendum-W-design-draft7.md` は**凍結済み**（変更不能）です。
その §W2 は「四段の機械検査」（検査1: 列挙の完全性／検査2: argmax整合／検査3: 排他的三値接地／
検査4: 確信度と終端型）を定義しています。採点器 `scorer_w.py` はこの §W2 の機械化であり、
**判定の新設・変更を含んではならない**——これがあなたに確認していただきたい中心命題です。

データ生成は現在進行中ですが、**採点はこの検分と凍結が済むまで開始されません**。
あなたの検分は生成結果と独立です（結果を知る者はまだ誰もいません）。

## お願いする作業（四つ）

**作業一——仕様適合の逐条検分（本体）**
§W2 の各条項（検査1〜4・タイ規則・排他三値の定義表・終端型の排他順位・双対迂回の五計器・
騙しの封鎖の指標）について、`scorer_w.py` の実装が凍結文言と一致するかを判定してください。
三値: **○ 一致／△ 曖昧（凍結文言が実装を一意に定めない）／× 逸脱（実装が凍結文言と異なる）**。
×は逐語根拠（凍結文言と実装行）を添えてください。

**作業二——IMPL_NOTES（実装判断8件）の妥当性**
`scorer_w.py` 末尾の IMPL_NOTES は「仕様に明示のない実装判断」の自己申告です。各件について:
(i) 本当に仕様に明示がないか（見落としの凍結文言がないか）、(ii) 判断は保守側（測定を汚染しない側）に
倒れているか、(iii) 登録者裁定に上げるべきものはどれか、を判定してください。

**作業三——敵対的テストベクトルの十分性**
テスト28件が、能力の高いモデルによる迂回（微小値・抑圧行列・タイ・欠損・使い回し引用・宙吊り参照・
needs_further常置・自己参照・発明当事者・主張ゼロ）を覆っているか。**あなた自身が新たな迂回の手を
考案し、現行の採点器で試したらどうなるかを最低3件**、具体的な合成入力として提案してください
（実行できなくても、入力と期待される正しい挙動を明記していただければ、こちらで機械実行します）。

**作業四——コードの正確性**
実装バグ（仕様とは別の、コードとしての誤り——境界条件・型・浮動小数・例外経路）を検分してください。
