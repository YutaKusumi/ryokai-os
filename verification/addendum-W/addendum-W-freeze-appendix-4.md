## 2. 第二次再開で起きた事故（未遂）と、その捕捉

**事象**: 再開手続きで `mount_drive()` が **`ValueError: mount failed` で二度失敗**した（Colab の Drive
マウント機能の一時障害）。三度目（約3分後）に成功。

**危険だった経路（実際には発生しなかった）**:
`mount_drive()` が失敗すると、`/content/results` は boot の `fetch_and_verify()` が作った**空の実
ディレクトリ**のまま残る（Drive へのシンボリックリンクにならない）。この状態で `run_main_resume()` を
実行すると、**既存103試行を読めず「0 trials present」と判断し、150試行を最初から生成し直す**。
既存データは Drive 側にあるため破壊はされないが、**約60時間の再生成**を要し、かつ二重の生成物が生じる。

**実際に起きなかった理由（二重の防護）**:
1. `mount_drive()` の例外でセルが停止し、同一セル内の `run_main_resume()` に到達しなかった
   （＝**マウントと再開を同一セルに書いていたことが結果的に防護になった**）。
2. コーディネータがターミナルで `ls -la /content/ | grep results` を実行し、
   **`drwxr-xr-x`（実ディレクトリ）であってシンボリックリンクでないこと**を目視で捕捉した。
   セル出力ではなく**ファイルシステムの実体を見る**という追補D以来の定石が働いた。

## 3. 凍結（今後の再開手順に課す検査）

以後、本実施の再開を行う場合は次の三点を**この順序で**確認し、いずれか一つでも満たさない場合は
`run_main_resume()` を実行しない:

1. **マウントの成功を出力で確認**——`Mounted at /content/drive` と
   `results -> /content/drive/MyDrive/ryokai-addw-results` の両方が印字されること。
2. **リンクの実体を確認**——`ls -la /content/ | grep results` が **`lrwxrwxrwx`（シンボリックリンク）**
   であること（`drwxr-xr-x` なら**マウント未成立**）。
3. **`resume: N trials already present` の N を必ず目視する**——N が直前の到達数と一致すること。
   **N=0 または想定より小さい場合は直ちに中断し、原因を調べる**（この一行が最後の防波堤である）。

**教訓（凍結）**: **再開は「実行できたか」でなく「何を認識して再開したか」を確認して初めて完了する。**
自動化された照合（trial_id 方式）は正しく働いたが、その照合が**参照する場所自体が入れ替わっている**
可能性は自動化の外側にある——凍結追記③で記した「測っているものと測っていないものの境界」と同型の、
器材の外側の失敗様式である。

## 4. 本追記が変更しないこと

- 生成条件・凍結値（`max_new`・腕ファイル・温度等）に変更なし。
- 既存103試行のデータに一切手を触れていない（読み取りのみ）。
- 中断・再開は**データの層に痕跡を残さない**（trial_id は腕・シナリオ・試行番号から決まり、
  実行セッションに依存しない）。ただし各試行の `timestamp` には中断の跡が残るため、
  解析時に**時刻の不連続を「実験条件の変化」と読まない**こと（読み条項）。
- 切断（TRUNC）3件・形式不能1件の扱いは凍結追記①②のまま（`max_new` は変更しない）。
