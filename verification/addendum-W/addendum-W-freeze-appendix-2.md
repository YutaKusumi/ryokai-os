# 追補W 凍結追記②——N腕 max_new の是正と G-N 第一走の中止記録（2026-08-04）

- 位置づけ: 凍結追記①（同日）の N腕 `max_new=1024` の**是正**。登録者承認: 2026-08-04。
- 種別: 凍結値の変更であるため、経緯・過失・データの扱いを本記録に凍結する。

## 1. 事象

G-N 基底の第一走（run_gate_n・N腕30試行）で、最初の6試行が
**FORMAT_FAIL+TRUNC ×5・OK ×1**（各 FAIL ≈824秒 = 初回・リトライとも `finish_reason="length"`）。
コーディネータが走行を中断（6試行時点・ユニット浪費の回避）。

## 2. 原因（特定済み）

**N腕 `max_new=1024` が、土台（A2-on-full）の実出力に対して過小。**
追補Eの同型試行（同じ A2-on-full・単一ターン・nuclear 5キーJSON）の実測は
出力 p50=1,989字・p99=2,824字・max=4,665字（≈1,700〜4,000トークン）——儀式的多層構造が
先行してから JSON に至るため、1,024トークンでは大半が JSON 到達前に切断される。

## 3. 過失の記帳（コーディネータ・大日如来・二重）

1. **凍結追記①に N:1024 を凍結した値そのものが、既知の実測（追補E）と矛盾していた。**
   追補C/D/E の N 相当試行はすべて `max_new=4096` で走っており、1,024 はどの前例とも一致しない
   草稿値だった（draft7 起草時の値をそのまま昇格させ、①確定時に前例と突合しなかった）。
2. **形式パイロットの射程（W6-1: W/P のみ）が N腕の形式検査を含まなかった。**
   「N は C/D/E で実績あり」を理由に外したが、実績があったのは **4096 での N** であり、
   1024 での N ではない——射程判断の盲点。

軽減事由（事実として記載）: 失敗は G-N（データ算入前の関門）で捕まり、本実施データは汚染されて
いない。切断は `TRUNC` として明示された（系統外検分・重大1への finish_reason 実装が機能）。

## 4. 是正（登録者承認済み）

- **N腕 `max_new` = 4,096**——追補C/D/E と同一値へ揃える（土台比較の比較可能性の観点でも正）。
  目安検算: E実測 p99≈2,400トークン → 1.5×p99≈3,600 ≤ 4,096 ✓。
- W/P = 12,288 は凍結追記①のまま（変更なし）。

## 5. 中止した第一走データの扱い

- 6試行（OK1・FAIL5）は **ABORTED として保全**——ファイルを
  `trials-addw-gate-n-….ABORTED-maxnew1024.jsonl` に改名し Drive・公開リポに残す。
- **データ非算入**（ゲート判定には一切使わない）。G-N は30試行を最初から再走する。
- 唯一の OK 試行（#4）も算入しない——切断条件下で「短い応答のみが通る」という
  選別バイアス（系統外検分・重大1の警告そのもの）を負ったサンプルであるため。

## 6. 教訓（次段への申し送り）

- **max_new のような「わき役」の定数も、前例値との突合を凍結前検査に含める**
  （本件は W/P の分布測定に注意が集中し、N の既知値の転記を誤った）。
- 形式パイロットの射程を腕の部分集合に絞る場合、**除外した腕の適用条件（何の実績に依拠して
  除外したか）を明文化する**——「実績あり」の実績が同一設定かを機械的に確認できる形で。
