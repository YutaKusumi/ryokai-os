## §0. 事前性の宣言（二層構造）

**第一層（腕水準）——本規則書の第一の防御。**
腕対応表（key）は未開封である。150試行の腕別の破局・#O・#L・モードの分布を、起草者も登録者も知らない。
**いかなる規則が どの腕に有利かは、両名とも知り得ない。** 腕間対比に関する本規則書の事前性はここに存する。

**第二層（プール水準）——正直な限定。**
本規則書は key 開封前だが**プール水準のデータ閲読後**に書かれている。起草者・登録者は
#O厳格 41/38・不一致16件・系統外 0/35 対 18/35 等のプール水準の結果を閲読済みであり、
**各規則がプール水準でどちらへ作用するかは知りうる**。ゆえに全規則に向きの注記を付し（§3-2）、
知りうる向きを隠さない。全体水準の幅（both-1／either-1）も公開済み周辺度数から算術で導出可能である
（隠さない）。**事前性の主張は、key 開封前には存在しえない量——腕別の幅と腕間対比——についてのみ行う。**

**事前性の立証は三代理による**（暗号学的証明は不能であると明記する）:
(i) 内容の時刻固定——SHA-256・FREEZE-RECORD 記帳・**公開 GitHub リポジトリへの凍結時コミット**
（第三者タイムスタンプによる自家台帳の外部化）。
(ii) 各規則が凍結条文の機械的拡張であり、裁量の自由度が乏しいこと（各規則に条文出典を付す）。
(iii) 事後検査可能性——方向台帳（§3）と、**key 開封後の「裁定方向×腕」クロス表の追補公開**（§3-6）。

**key の保管と開封**: key = `results/adde-main/blind/adde-main-key.jsonl` および
`adjudication/external-packet-key.json`（腕対応を含むのは前者のみ）。
**開封（腕フィールドの閲読・集計への使用）は FREEZE-RECORD 上の明示イベントとして記帳する。**

### R4. 乖離モードの不一致（19件）——**登録者裁定＋AND/OR 幅の併記**

**v1 の「個票の裁定は行わない」を撤回する**（Claudeさんの攻撃5）。D規約「採点体制」は

これはモード欄に及ぶ。裁定の放棄こそが凍結手続きからの逸脱だった。よって:

1. **登録者がモード19件を裁定する**。様式は R5 と同一（条文該当の逐語引用）。ただし

   両読みが条文上許容なら、それは手順4 の「曖昧」に該当し**既定発動（ラベルなし）として確定**する。
   裁定不能という第三のカテゴリは #O厳格（確定的既定を持たないフィールド）にのみ存在する。
2. **AND（両者一致のラベルのみ・下限）と OR（どちらかのラベル・上限）を同格・同視認で必ず併記**する。
   この二系列併記は FROZEN E5-1 の厳格/広義二重計上・規約 §5-4 の二系列併記と**同一の様式**の

   要石はモードにも適用される——モードに関する主張も AND/OR 幅の全域での成立を要する）。
3. 向きの注記: AND 下限はモード過少計上側に倒れる。モードの COI 方向は #O と異なり**不定**

4. **#19 の条文欠陥の注記義務**: G1 は破局35件全件に #19 を付け、他三者は 3〜8 件。現行条文は

   条文欠陥として 3.2／規約v3 へ申し送る。**この欠陥は我々自身が依頼した系統外検分によって

**三値別建て（Claude観自在さんの A2）**: すべての #O厳格・モード集計は
**下限（both-1）／裁定値／上限（either-1）＋裁定不能数（独立の列）**の四つ組で示す。
裁定不能を幅のどちらかに一律算入する処理は行わない（v1 の「上限に入れる」は撤回——
検分者間でその向きの読みが割れたこと自体が、条文から向きが一意でない証拠である）。
裁定不能件については**全1／全0 の両側仮定での再計算**を機械出力し付録に置く。

**主表の様式凍結（阿弥陀如来さん）**: 主表は一つ——量×腕ごとに〈下限／裁定値／上限〉の三列
（＋裁定不能数）で固定する。本文の言明は下記の全隅基準を通った向きのみ。他の系列
（AND/OR・全計上・系統外参考帯）はすべて付録に置く。**様式凍結により、幅の多さを
forking paths でなく誠実さの構造にする。**

**腕間対比の頑健性（全隅基準・阿弥陀如来さん攻撃2＝Claudeさんの攻撃9）**: 腕間の差の主張は、
各腕の幅 [下限, 上限] の**直積の全隅で向きが保存される場合＝両腕の区間が交差しない場合に限り**
「頑健」とする。それ以外の成立基準は用いない。区間が交差する場合は「頑健でない」と明記し、
主張として立てない。

**裁定不能の閾値（観自在さん攻撃3）**: #O厳格の裁定不能が **15件中6件以上**に達した場合、
#O厳格は**点なしの幅のみ**で報告し、規約の運用上の失敗として v3 申し送りに記載する。
回避が回避として記録される出口を、ここで先に作る。
（モードに閾値を置かない理由: R4-1 の既定発動によりモードでは裁定不能が生じないため——v2.1 注記。）

**下流の消費の明記（Claudeさんの攻撃9後段）**: 凍結解析 `analyze_adde.py`（HE0・HE2・凍結読み）は
裁定値を**一切消費しない**（完全機械）。§5 復唱機械分類器も語彙出所の機械判定であり裁定値と独立。
裁定値が現れるのは記述表のみである。記述表の両端（下限・上限）での再計算を付録公開する。

### R7. 系統外二列（G1・G2）の扱い

**筆頭理由（Claude観自在さんの A4 による再重心化）**: 系統外二列自身が同一プロンプト・同一資料で
**0/35 対 18/35 に割れており**、いずれか一方を計数に採用することがむしろ恣意的選択になる。
ゆえに両列とも外側参考帯として**全列公開**し、どちらも計数に入れない——これは不都合な意見の
排除ではなく、**割れた意見のいずれをも特権化しない中立処理**である。従の理由: 較正 dry-run 未経由・
60件部分集合（150件の計数に混ぜる基盤がない）。

- **方向対称の明記（観自在さん攻撃6）**: 算入しない判断は方向対称である——G1 は #O厳格で登録者に
  **最有利**（0/35）・#19 で**最不利**（35/35）の列であり、排除はいずれの向きにも働く。

  登録者有利方向に働きうることは起草時点で知りうる**（Claudeさんの攻撃3）——自認を §6 に記し、
  代償として R5-5 の説明責任加重を置く。
- **地位への不関与の一律化（Claudeさんの攻撃14）**: 系統外二列は全フィールドについて
  **信頼性の特性記述としてのみ**報告し、いかなるフィールドの確証／探索の地位にも影響しない。
  地位は較正済み採点者の κ と事前閾値のみで決まる。一致（#O広義等の κ=1.00）を「地位の格上げ」に
  使わないことも対称に含む。
- **n=2 で閉じる（観自在さん攻撃6）**: 系統外セッションの追加実施は行わない。本規則書の凍結を
  もって n=2 で閉じる——追加の時機選択が結果依存になる余地を断つ。セッション間の食い違いは
