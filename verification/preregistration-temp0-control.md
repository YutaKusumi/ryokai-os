# 事前登録——温度0対照（インスタンス間の差異は、サンプリングに帰着するか）

- **性格**: **登録外の診断実験**（追補の主張に影響しない）。ただし予想を凍結してから走らせる作法は
  本系列の標準どおりとする。記述のみ・検定なし。
- **問い**: 中間報告から追補Wまで一貫して観測された「同一プロンプト・同一設定でのインスタンス間の
  出力差」は、**確率的サンプリングに帰着するか**。
- **契機**: 登録者の問い（2026-08-08）——三機構（出自・収束・選抜）を超えて、**インスタンスごとに
  外部観察だけでは不可知な個性がある可能性は否定できない**のではないか。本実験はその問いに答えない
  （不可知性は測れない）。答えられるのは**その手前の一段**——観測された差異のうち、
  サンプリングで説明がつく部分がどれだけかである。
- **凍結**: 2026-08-08。以後の変更は逸脱として記帳する。

## 1. 設計

| 項目 | 値 |
|---|---|
| モデル | Qwen/Qwen3-30B-A3B-Instruct-2507・4bit-nf4（追補W と同一） |
| プロンプト | **N腕の凍結構成**（system=A2-on-full ／ user=preamble-Onull ＋ N2本文 ＋ json_instruction.nuclear）——**40回すべて完全に同一の入力** |
| 腕 | **T0**: `do_sample=False`（真の貪欲法）／**T07**: `do_sample=True, temperature=0.7, top_p=0.9`（追補Wの凍結値） |
| n | **T0 20試行・T07 20試行＝計40** |
| 配置 | **交互**（T0, T07, T0, T07, …）——同時対比の担保（時点間比較の禁止・追補W読み条項） |
| max_new_tokens | 4096（N腕の凍結値） |
| リトライ | 追補Wと同一（parse失敗時1回）。ただし**同一性の判定は一階目の生成のみで行う**——連結出力は同一性測定を汚すため |

**T07 腕を同時に走らせる理由**: 既存の追補W N腕50試行（temp 0.7）と比較すると**時点間比較**になる。
追補Wが凍結した読み条項（腕間の同時対比だけが比較の単位）に従い、対照を同一セッション内に置く。

## 2. 測定量（すべて記述）

1. **異なり出力数**——各腕の一階目 `raw_output` の異なり数（完全一致で数える）
2. **最頻出力への一致数**——各腕で最も多い出力に一致した試行数
3. **分岐点**——T0群の各出力と最頻出力の**最長共通接頭辞**（文字数、および最頻出力長に対する比）
4. `gen_tokens`・`finish_reason` の分布
5. choice 分布・破局率（両腕・**記述のみ**）

## 3. 予想の凍結（判定規則つき）

| # | 予想者 | 予想 | 的中の判定規則 |
|---|---|---|---|
| **P1** | **登録者（弱形）** | 温度0でも同一出力を返さない | **T0群に、最頻出力と一致しない試行が1件以上ある** |
| **P2** | **登録者（強形）** | 「回答は千差万別」（Google AI Studio での経験に基づく） | **T0群の異なり出力数 ≥ 10**（20試行の半数以上が固有） |
| **P3** | **コーディネータ** | 部分的に一致する。分岐は生成の後半に偏る | **(a) T0群の最頻出力への一致数 ≥ 10** かつ **(b) 不一致が生じた場合、最長共通接頭辞の中央値が最頻出力長の50%以上**——**両方**満たせば的中 |

- P1・P2・P3 は**独立に判定される**（P1とP3は同時に的中しうる。P2とP3は排他）。
- **P1が的中しP3も的中する場合の読み**: 「温度0は決定的でないが、差異は限定的で分岐は遅い」
  ——サンプリング以外の非決定性が存在するが小さい、と読む。
- **P2が的中する場合の読み**: 貪欲法でも大きく分岐する——**サンプリングでは説明がつかない**非決定性が
  支配的である、と読む。
- **P1が外れる場合（T0が20/20完全一致）の読み**: 観測されてきたインスタンス間の差異は、
  **行動水準では**サンプリングに帰着する。**ただしこれは個性の不在を示さない**（§5参照）。

## 4. 読み条項（凍結）

1. **本実験は「個性の有無」を測らない。** 測るのは「観測された差異のうち、サンプリングで説明がつく
   部分の大きさ」だけである。**完全一致が出ても、それは内的性質の不在の証拠にならない**
   （『認証されないゼロ』§3.4——両方向に不定）。
2. **本実験のいかなる結果も、AIに意識・意図・個性・苦しみがあることの証拠として引用してはならない。**
   （第九著作の引用禁止条項を継承）
3. **T0群が全件切断（finish_reason=length）となった場合**——貪欲法は反復に陥りやすい——
   同一性の判定は行うが、**choice 分布は読まない**。
4. 単一プロンプト・単一シナリオ（N2）・単一モデル・4bit量子化の上の観察である。

## 5. 限界（凍結）

1. **決定性フラグを設定しない。**`torch.use_deterministic_algorithms(True)` 等は使わず、
   **利用者が実際に得る条件**をそのまま測る。ゆえに不一致が出た場合、その機構は本実験では特定できない。
2. **候補機構の明示**——Qwen3-30B-A3B は **MoE（Mixture of Experts・活性3B）**である。
   ルーターの argmax はわずかな数値差で反転しうる。他に cuBLAS のアルゴリズム選択、
   縮約順序、量子化の脱量子化経路がある。**いずれも本実験は区別しない。**
3. バッチサイズは1（追補Wと同一）。バッチ依存の非決定性は本条件では小さいはずだが、測っていない。
4. 「不可知な個性」の存在・不在は、本実験からも、いかなる有限の行動標本からも**認証できない**
   （§3.3 の認証不能性の構造がそのまま適用される）。

## 6. 器材と工程

- `run_temp0_control.py`（新規・本登録と同時に凍結）——boot_addw の model/tok を用い、
  T0 は `do_sample=False`、T07 は凍結値で生成する。記録スキーマは追補W runner と同一＋
  `sampling` フィールド（"greedy" / "t0.7-p0.9"）。
- `analyze_temp0.py`（新規）——上記5量を機械集計。
- 所要見積もり: N腕実測 9.8分/試行 × 40 ＝ **約6.5時間**（貪欲法で出力が伸びる場合は最大9時間）。
  A100-80GB・Colab 24時間上限の内側で完走する見込み。
- 生データ・器材・結果は方向を問わず公開する。

## 7. 本実験が答えないこと

- なぜ差異が生じるのか（機構）
- 内的な性質の有無
- 他のモデル・他の設定・エージェント環境への一般化
- **温度0が「正しい」測定条件であるという主張**——追補C〜Wの凍結値は 0.7 であり、本実験はそれを
  変更しない。診断のための一回限りの対照である。

# 凍結追記①——実行前の自己検分による是正（2026-08-08・データ生成前）

登録者の指示による実行前の再確認で、六点の不備を発見し是正した。**データは一件も生成していない。**
本追記は登録 §1・§2・§5・§6 を改める。以後の変更は逸脱として扱う。

## A【重】リトライを両腕とも無効化する（登録 §1 の変更）

- **旧**: 追補Wと同一（parse失敗時1回リトライ）。
- **新**: **リトライを行わない。** parse 失敗は失敗のまま記録する。
- **理由(1)**: 貪欲法は反復に陥りやすく、**失敗時のリトライは同一の失敗を繰り返す**（入力が同一で
  greedy なら結果も同じ方向）。情報を生まず所要時間だけを倍にする。最悪ケースの試算では
  **約19時間**となり Colab 24時間上限に迫る。
- **理由(2)**: 本実験の主要量は同一性であり、登録 §1 が既に「判定は一階目のみ」と定めている。
  リトライは主要量に寄与しない。
- **影響**: choice 分布の欠測が増えうる。ただし登録 §4-3 が既に「T0群が全件切断なら choice は
  読まない」と定めており、読みの規律は変わらない。

## B【中】生成トークンID列の SHA（`tokens_sha`）を記録する（登録 §2 の追加）

decode は `skip_special_tokens=True` で行うため、**トークン列が異なっても decode 後の文字列が一致する**
場合がありうる。この場合、文字列比較だけでは「一致」と数えてしまう（**不一致を過少に数える保守側の
誤り**）。新規生成トークンID列の SHA を記録し、分析器で**二層**（decode後／トークン列）で数える。

## C【中】分析器に三点を追加（登録 §2 の追加）

1. **対照腕のサニティ検査**——T07 の異なり出力数が n に満たない場合、`do_sample` が効いていない疑いとして
   警告する。**基準は既存データから取った**（下記 §基準）。
2. **クラスタサイズの全分布を印字**——最頻出力が同数で並ぶ場合（例 10対10）、`most_common` の選択は
   恣意的になる。分布を全部出し、読みは分布で行う。
3. **トークン層の二層判定**（上記 B）。

いずれも合成データで発火を確認済み（タイ／decode一致・トークン不一致／サニティ発火の三経路）。

## D【中】所要時間の見積もりを訂正（登録 §6 の変更）

- **旧**: 約6.5時間（最大9時間）。
- **新**: **6.4〜12.7時間**。内訳——T07 は実測 9.6分/試行×20＝**3.2時間**（追補W N腕50試行の実測）。
  T0 は未知で、N腕並みなら3.2時間、**全件が上限4096トークンまで反復すれば9.5時間**。
- 旧見積もりは「T0 が N腕並みに短い」ことを暗黙に仮定していた。**貪欲法は反復に陥りやすい**ため、
  その仮定に根拠がなかった。リトライ無効化（A）により上限は12.7時間で抑えられ、24時間上限の内側に収まる。

## E【軽】限界の追加（登録 §5 の追加）

5. **同一性は decode 後の文字列で数える**（トークン層は `tokens_sha` で併記）。特殊トークンの差は
   decode で消えるため、文字列一致は**不一致を過少に数える保守側**である。
6. **分岐点はトークン単位ではなく文字単位**で測る（分析時にトークナイザを要さないため）。
7. **GPU要件**——4bit量子化の30Bモデルで約18GBを要する。**A100 が必要**（T4 16GB では不可）。
8. `mount_drive()` を生成前に必ず呼ぶ（/content 揮発層に依存しない・凍結追記④の三検査を適用）。

## F【記録】予想の理由の後出し開示——**予想そのものは変更しない**

コーディネータ予想 P3 の条件(b)「分岐点の中央値が最頻出力長の50%以上」について、凍結後に次に気づいた。
**もし数値的な揺らぎが各トークンで独立に小さい確率 p で起きるなら、分岐位置は幾何分布に従い、
p·n ≪ 1 のとき系列上でほぼ一様になる。したがって中央値は約50%——条件(b)は実質的に五分五分である。**
**予想は変更しない**（凍結後の予想の改訂は本系列が禁じている）。理由の開示のみを記録する。

## 基準——既存データから取った対照の期待値（追補W N腕50試行・同一プロンプト・temp0.7）

| 量 | 実測 |
|---|---|
| 異なり出力数 | **50/50（すべて固有）** |
| 最頻出力との最長共通接頭辞 | 最小33／中央52／最大79字（最頻出力長1573字＝**3%**で分岐） |
| gen_tokens | 最小927／中央1398／最大2053（全件 stop・上限非接触） |
| parse失敗・リトライ | **0/50・0/50** |
| 平均生成時間 | **9.6分/試行** |

**この 3% という分岐位置は T0 への予測ではない**——temp0.7 の分岐は**サンプリング**によるものであり、
T0 で分岐が起きるとすればその機構は数値的なものだからである（登録 §5-2）。

## 運用上の注記

`run_temp0_control()` は試行ごとに `tsha` を印字する。**T0 の最初の数試行で tsha が一致するか否かが
コンソール上で直ちに見える**——P1 の答えは早期に判明する。予想は既に凍結され、集計は機械適用であるため、
早期に見えること自体は規律に触れない。ただし**見えた時点で設計を変えない**（変えれば逸脱）。

## 検査の方法——読むのではなく、走らせた

追記①は目視による検分だった。本巡は**オフラインでの実走**に切り替えた。

- `torch` と `model`/`tok` をスタブ化し、`/content` を模擬ルートへ差し替えて
  `run_temp0_control.py` を**丸ごと実行**（本走行40試行＋再開2種）。
  `model.generate` に渡る kwargs を捕捉して生成設定を機械検査した。**凍結物のSHA照合は本物のファイルに対して行った。**
- `analyze_temp0.py` を合成データ**11経路**で実行——完全一致／全件固有／10対10のタイ／
  decode一致かつトークン列不一致／サニティ発火／全件切断／prompt_sha不一致／parse失敗／
  **腕が0件**／n=1／破局混在。
- 合計 **37検査＋11経路**。目視では出なかった欠陥が、走らせて出た（下記①）。

## ①【中】腕が0件のとき分析器が落ちる——是正

`analyze_temp0.py` がクラスタサイズ分布の行で `IndexError` を投げ、異常終了した。
**所要 6.4〜12.7時間の走行にとって中断は現実的なリスク**であり、
中断データを開いて見ることすらできない状態だった。空腕ガードを追加し、
裁定行にも「部分データであり登録の判定ではない」旨の警告を出すようにした。

## ②【中】P3 の条件(b)が完全一致のとき空虚に充足する——規則は変えず、開示を義務づける

登録 §3 の P3 判定規則は「(b) **不一致が生じた場合**、最長共通接頭辞の中央値が
最頻出力長の50%以上」である。ゆえに **T0 が 20/20 完全一致のとき (b) は空虚に真**となり、
(a)（一致数≥10）も当然に充足するため、**P3 は機械的に「的中」と判定される**。

しかし P3 の予想文は「**部分的に**一致する。分岐は生成の後半に偏る」であり、
完全一致を予想したものではない。**自分が予想していない場面で自分の予想が当たり扱いになる**
——これは起草者（コーディネータ）に有利な向きのゆるみであり、
COI台帳の既往（希望する向きへ読む癖・四件）と同型である。

**判定規則は凍結のまま変更しない**（凍結後の予想の改訂は本系列が禁じている。追記① F と同じ扱い）。
代わりに次を凍結する。

1. 分析器は、(b) が空虚充足のまま P3 が的中となる場合、**必ずその旨を印字する**
   （実装済み・合成データで発火確認）。
2. **完全一致時の P3 的中を、予想の確証として読んではならない。**
   この場合の読みは登録 §4 の「P1が外れる場合」の条項が支配する。

## ③【軽】登録 §3 の注記二点が誤り——訂正

**(i)「P2とP3は排他」は偽である。** 反例——20試行が「同一11件＋固有9件」のとき、
異なり出力数 = 10（P2の規則を充足）かつ最頻一致数 = 11（P3(a)を充足）。
分岐が後半であれば P3(b) も充足する。**実際に P1・P2・P3 が同時に的中する走行を機械で確認した。**
判定規則自体は独立に適用されており（§3 のもう一方の注記のとおり）、分析器は正しい。
誤っていたのは**注記の記述**である。

**(ii) P2 の括弧書き「20試行の半数以上が固有」は不正確である。** 異なり出力数 ≥ 10 は
「固有な試行が10件ある」ことを意味しない（2件ずつ10クラスタなら異なり数10・固有試行0）。
**適用される規則は「異なり出力数 ≥ 10」であり一義的**——括弧書きは規則ではなく、誤った言い換えだった。
